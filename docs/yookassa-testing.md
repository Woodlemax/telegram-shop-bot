# Проверка оплаты ЮKassa

Источник данных карт и причин отказа: [официальная документация ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing#test-bank-card-data).
Матрица сверена 9 октября 2026 года.

## Автоматические проверки

Тесты работают с локальным HTTP-сервером, временной SQLite и поддельным Telegram API. Ключи магазина, доступ в интернет и настоящие карты не нужны. Они проверяют обработку ответов ЮKassa в приложении; ввод карт и работу банков/3-D Secure эти тесты не воспроизводят.

- `TestYooKassaHostedCardPaymentStates`: ожидание ввода карты/3-D Secure, авторизация без списания, отказ, некорректная комбинация succeeded/paid=false, подтверждённый тестовый платёж с точной суммой в копейках.
- `TestYooKassaTestCardDeclineThenSuccessfulRetry`: все 13 комбинаций party/reason из приведённой ниже таблицы. Отказ и ложное уведомление об успехе не записывают оплату, не уменьшают запас, не выдают ZIP и оставляют заказ pending. Новая успешная попытка оплачивает тот же заказ и выдаёт архив один раз. Поздний отказ первой попытки и повторное уведомление об успехе не отзывают доступ и не дублируют выдачу.
- `TestYooKassaMiniAppResumeAfterProviderError`: сбой API при создании ссылки возвращает 502; повтор в Mini App создаёт ссылку по сохранённой сумме заказа с сохранённым ключом идемпотентности. Сумма из клиентского запроса игнорируется; заказ и платёжные записи не дублируются.
- `TestYooKassaPollingIgnoresIncompleteCardPayments`: резервная проверка платежей не подтверждает pending, waiting_for_capture или canceled, даже если такой объект попал в ответ провайдера.

Запуск:

```sh
go test ./internal/payment ./internal/bot ./internal/webapi ./worker -run 'YooKassa|DigitalArchiveYooKassa' -count=1
```

## Проверка настоящей тестовой страницы оплаты

Использовать только магазин с тестовым ключом. У ответа ЮKassa должно быть `test: true`. Настоящие карты в тестовой форме не применять. Stars — отдельный способ оплаты; подключение тестовой ЮKassa не делает Stars тестовыми.

Для всех карт ниже можно указать срок 12/30 и CVC 123. При наличии 3-D Secure ввести произвольный числовой код на тестовой странице. Номера ниже — публичные тестовые данные ЮKassa.

### Успех

| Карта | Номер | 3-D Secure |
| --- | --- | --- |
| Mastercard | 5555 5555 5555 4477 | Да |
| Mastercard | 5555 5555 5555 4444 | Нет |
| Visa | 4793 1281 6164 4804 | Да |
| Visa | 4111 1111 1111 1111 | Нет |
| Мир | 2200 0000 0000 0004 | Да |
| Мир | 2202 4743 0132 2987 | Нет |

1. В Mini App добавить самолёт со свободной ценой 100 ₽ и выбрать оплату в рублях.
2. Убедиться, что открывается страница ЮKassa. До подтверждения оплаты архив недоступен.
3. Оплатить одной из тестовых карт; повторить с картой без 3-D Secure и с другой платёжной системой.
4. Вернуться к боту и открыть Mini App. Если HTTP-уведомления не настроены, дождаться резервной проверки раз в минуту.
5. Проверить оплату заказа, доступ к скачиванию и одну автоматическую отправку ZIP.
6. Повторное уведомление об успехе не должно повторно отправлять ZIP. Повторное скачивание по кнопке допустимо.

После отказа:

1. В кабинете/API ЮKassa проверить canceled, paid=false и соответствующие cancellation_details.

4. После подтверждения файл становится доступен. Отмена предыдущей попытки не отменяет уже оплаченный заказ.

### Прерванная оплата

Закрыть платёжную страницу до завершения ввода карты или 3-D Secure. Заказ не должен стать оплаченным, архив остаётся закрытым. Повторный переход из истории заказов должен открыть ту же действующую ссылку оплаты. Новая ссылка появляется только после подтверждённого canceled у предыдущего платежа.

### ЮMoney

На странице ЮKassa выбрать кошелёк ЮMoney и нажать «Заплатить». В тестовом магазине реальный кошелёк не нужен. Затем проверить тот же доступ к архиву и отсутствие повторной выдачи.

## Границы проверки

Автоплатежи и сохранение карт не входят в текущий сценарий магазина с разовой redirect-оплатой. СБП и другие способы, которые документация разрешает проверять только в настоящем магазине, этой тестовой матрицей не подтверждаются.

Ручные пункты выше — инструкция, а не отчёт об исполнении. Автоматические тесты не подтверждают прохождение реальной страницы ЮKassa или фактическую доставку файла в Telegram.

## Защита от нескольких страниц оплаты

Бот и Mini App используют одну запись платежа на заказ и магазин ЮKassa. Повторное открытие pending-платежа возвращает ту же ссылку. Запись и ключ идемпотентности сохраняются в SQLite; перезапуск сервиса не создаёт новую попытку. Описание и return_url первого запроса фиксируются, чтобы повтор с тем же ключом имел идентичное тело.

Новый платёж разрешён только после получения canceled/paid=false через API ЮKassa. Ошибка чтения состояния, waiting_for_capture или succeeded блокируют создание ещё одного платежа. При неизвестном результате POST повторяется прежний запрос; после 23 часов такой неизвестный результат требует проверки, поскольку ЮKassa гарантирует идемпотентность только 24 часа.

Регрессии: TestYooKassaTwoPaymentPagesReuseOneInvoice, TestYooKassaCheckoutConcurrentBotAndMiniAppShareOnePayment, TestYooKassaCheckoutSurvivesDatabaseReopen, TestYooKassaCheckoutConcurrentCanceledRotationCreatesOneReplacement и TestYooKassaCheckoutLostCreationResponseReusesFrozenRequest. Проверяются также просроченный неизвестный результат, изменённая сумма, оплаченный/отменённый заказ и needs_review.

Перед выдачей счёта способ оплаты атомарно закрепляется за заказом. После открытия ЮKassa нельзя получить или подтвердить счёт Stars того же заказа; после выбора Stars нельзя создать платёж ЮKassa. Telegram pre-checkout повторяет проверку, включая ранее открытые счета Stars. Выбор сохраняется при перезапуске, закрытии платёжного окна и неизвестном результате запроса к провайдеру. История показывает только выбранный способ. Смена способа у этого заказа не предусмотрена: закрытие окна не отменяет внешний платёж. Повторная оплата выбранным способом остаётся доступна по прежним правилам.

Миграция закрепляет ЮKassa за существующими checkout-intents. Отдельные ссылки, выданные ещё до сохранения таких записей, невозможно автоматически восстановить из базы. Уже фактически полученный второй платёж сохраняется с needs_review.

Регрессии общего выбора: TestYooKassaBlocksStarsInvoiceAndAlreadyOpenedStarsPreCheckout, TestStarsApprovalBlocksYooKassaBeforeItsAPI, TestConcurrentYooKassaCreationAndStarsPreCheckoutOnlyOneRailWins, TestLostYooKassaCreationResponseKeepsStarsBlocked, TestCheckoutProviderSurvivesReopenAndRejectsOtherRails, TestCheckoutProviderMigrationBackfillsExistingYooKassaIntent и TestOrderPaymentSelectsOneRailAndHidesTheOther. Они используют имитацию провайдеров: фактического списания денег или Stars не выполняют.

Дополнительная проверка настоящего API: TestYooKassaCheckoutLiveTestMerchantReusesPayment запускается только с RUN_YOOKASSA_LIVE_TESTS=1 и переменными YOOKASSA_TEST_SHOP_ID, YOOKASSA_TEST_SECRET_KEY, YOOKASSA_TEST_RETURN_URL. Сначала проверяет /me и запрещает любые операции для настоящего магазина. Создаёт один неоплаченный тестовый платёж для изолированного локального заказа, повторно открывает его из другого экземпляра сервиса и проверяет совпадение ссылок. Оплата и заказ в рабочем магазине не создаются. Ключи передаются через окружение, в выводе теста их нет.

Срок гарантированной идемпотентности: [документация ЮKassa](https://yookassa.ru/developers/using-api/interaction-format#idempotence).
